1. What is Amazon Bedrock -

  * It is a fully managed AWS service for building Generative AI applications using Foundation Models
  
  * Bedrock provides you multiple Foundation Model under the hood, thus one can switch to different
    Models as and when required with minimal changes
  
  * It is a SERVERLESS service i.e AWS handles the underlying infracstructure

2. Fine Tuning a Model -

  * Using Supervised and Reinforcement tuning, Supervised Fine-Tuning is usually CHEAPER as computations 
    are less intense and less data is usually required

  * Distillation -

    AWS Bedrock describes Distillation as transferring knowledge from Larger, more capable TEACHER to 
    smaller, faster and more cost efficient STUDENT
    i.e Large Model => Small Model

3. Model Evaluation -

  * Now since we have fine tuned a model, to know whether it is performing good or not we need to evaluate
    the model

  * Evaluation Approaches -
    
    * Automatic / Programmatic Evaluation -

      Your provide a dataset and evaluate the model automatically

    * Human Evaluation -

      Human assesses the Outputs of the model

    * LLM based Evaluation -
      
      One model evaluates the performance of Another model
      Model A => Answer => Judge Model => Score the Output
      
4. RAG and Knowledge Bases in Bedrock -

  * Bedrock Knowledge base -

    * It sits between the data, embeddings, vectors and Foundation model
      
      Your Data
        ↓
      S3 / other supported data source
        ↓
      ┌──────────────────────────────┐
      │ Amazon Bedrock Knowledge Base│
      │                              │
      │  • Ingests data              │
      │  • Chunks documents          │
      │  • Creates embeddings        │
      │  • Stores them in vector DB  │
      │  • Retrieves relevant chunks │
      └──────────────┬───────────────┘
                     ↓
              Vector Store
                     ↓
              Retrieved context
                     ↓
              Bedrock Foundation Model
                     ↓
                   Answer 
    
    * It solves the problem of injecting data, creating Chunks, then creating embeddings and then
      storing them in vector DB and then retrieving the relevant chunks
      Otherwise all these needs to be done manually
  
  * RAG Datasources -

    The place where your original data is stored is termed as RAG Datasource
    
    Possible RAG Datasources - Amazon S3, SharePoint, Confluence, Google Drive, Website, Redshift

5. Bedrock Guardrails -

  * KBs = It tells what information my AI can retrieve
    Guardrails = It tells what should my AI be allowed to Say or Receive

  * It acts as a Security Filter 
    User => Guardrail checks Is this allowed? => LLM => Guardrail checks Is this response allowed? => 
    User

  * | Guardrail capability              | Meaning                                                                                                                              | Simple example                                                       |
    | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
    |   Content Filters                 | Blocks harmful or inappropriate content such as hate, violence, sexual content, insults, misconduct, and prompt attacks.             | User asks for harmful instructions =>    Block                        |
    |   Denied Topics                   | Prevents the model from discussing specific   topics   that your application doesn't allow.                                          | Banking bot => deny   investment advice                               |
    |   Word Filters                    | Blocks specific   words or phrases   that you configure.                                                                             | Block a competitor name or offensive term                            |
    |   Sensitive Information Filters   | Detects sensitive information/PII and can   block or mask   it.                                                                      | `SSN: 123-45-6789` => `SSN: {SSN}`                                    |
    |   Contextual Grounding            | Checks whether the model's response is   relevant to the question and supported by the provided context  , especially useful in RAG. | Document says 20 days leave, model says 50 =>    Flag/block           |
    |   Automated Reasoning             | Checks whether the model's response follows   defined logical rules or policies  .                                                   | Rule: only recommend products in stock => validate the recommendation |

6. Bedrock Agent -  

  * It is used to create AI Agents, and can be used where Multi Step tasks are involved

  * Action Groups - It defines actions that an Agent can perform by interacting with your applications
    API's
  
  * We can connect Action Group to Lambda as well
    Bedrock Agent => Action Group => Lambda => Your business logic => Database / API / application

7. Bedrock Logging -

  * It needs to enabled and can be stored in S3 or CloudWatch 

  * It can stores various attributes such as RequestID, Input Token Count, Ouptut Token Count, Model ID
    etc

  * CloudWatch metrics - 
    ContentFilteredCount - helps to see if Guardrail is functioning or not

8. Bedrock Pricing -

  OnDemand - Pay as you Go
  Batch - Muliple predictions at a time(output in a single file), upto 50% discount
  Provisioned throughputs - Purchase Model units for certain time say 1 month, 6 months etc

9. AWS SageMaker -

  * SageMaker  - End-to-End ML service

  * SageMaker Automatic Model Tuning - tune hyperparameters

  * SageMaker Deployment & Inference - real-time, serverless, batch, async

  * SageMaker Studio - unified interface for SageMaker

  * SageMaker Data Wrangler - explore and prepare datasets, create features

  * SageMaker Feature Store - centrally stores, manages, and shares ML features for training 
    and inference

  * SageMaker Clarify - compare models, explain model outputs, detect BIAS at a point in time

  * SageMaker Ground Truth - RLHF, humans for model grading and data labeling

  * SageMaker Model Cards - ML model documentation

  * SageMaker Model Dashboard - view all your models in one place

  * SageMaker Model Monitor - monitoring and alerts for your model, detect bias after monitoring

  * SageMaker Model Registry - centralized repository to manage ML model versions

  * SageMaker Pipelines - CICD for Machine Learning

  * SageMaker Role Manager - access control

  * SageMaker JumpStart - ML model hub & pre-built ML solutions

  * SageMaker Canvas - No-code interface for SageMaker

  * MLFlow on SageMaker  - use MLFlow tracking servers on AWS

  * Network Isolation mode - 

    * Run SageMaker job containers without any outbound internet access

    * Can’t even access Amazon S3

  * SageMaker DeepAR forecasting algorithm -

    * Used to forecast time series data

    * Leverages Recurrent Neural Network (RNN)
