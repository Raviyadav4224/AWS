1. AWS Regions -

    AWS Region is a geographical area that contains multiple Availability Zones AZ.
    Each region operates independently to reduce latency and fault tolerance

    Examples -
        In India we have Asia Pacific (Mumbai), US East
            ap-south-1 (Mumbai)
            ap-south-2 (Hyderabad)
            ap-southeast-1 (Singapore)
            me-central-1 (UAE - Dubai)

    ** Each AWS Region consists a minimum of 3 AZ's

2. Availability Zones (AZs) -

    Each Region has a multiple AZs which are physically separated data centers within that region
    These AZs are connected with low latency networking but are far enough to ensure disaster recovery.
    If one region goes down, other remains functional

    Examples -
        Mumbai region (ap-south-1) has 
            ap-south-1a
            ap-south-1b
            ap-south-1c

3. AWS Data Centers -

    AWS Data centers are physical building where AWS servers and networking equipments are housed

    * Edge locations and AZ contains Data centers which are smaller in size and differs in purpose

    ** Each AZ contains ONE or MORE discrete data centers in the same location

4. AWS Edge Locations -

    AWS Edge Locations are data centers used for caching content and reducing latency.
    These are used by AWS CloudFront (CDN), Route 53 etc
    Egde locations in India -
        Mumbai, Hyderabad, Delhi, Kolkata, Chennai, Bengaluru

5. AWS Shared Responsibility Model -

    * AWS manages and secures the underlying cloud infrastructure such as physical servers, networking, 
      storage hardware, and data centers
    
    * The customer is responsible for what runs inside the cloud, including application code, 
      IAM permissions, operating system configuration, security groups, and data security

    * For example, AWS ensures that an EC2 server is available and functioning, but the customer is 
      responsible for the application running on that EC2 instance

    *   | Service | AWS manages             | Customer manages          |
        | ------- | ----------------------- | ------------------------- |
        | EC2     | Hardware + infra        | OS + app                  |
        | RDS     | OS + DB patching        | DB schema + data          |
        | Lambda  | Almost everything infra | Function code             |
        | S3      | Storage infra           | Bucket policies + objects |

6. AWS Pillars -

    * Operational Excellence - Monitoring
    * Security - IAM
    * Reliability / Resiliency - Recover from failures automatically, ability of a workload to perform its
      intended function correctly and consistently
    * Performance Efficiency - Use resources efficiently
    * Cost Optimization - Spend only what you need like Savings plan
    * Sustainability - Reduce environmental impact

    * Durability - Stores data consistently without disruptions
    * Elasticity - ability to acquire resources as you need and release when you no longer need them
    * Agility - Speed with which one can acquire resources in AWS
    
7. AWS Plans -

    * Developer => Business hours, Trusted Advisor Core, technical support
    * Business => 24×7 technical support, Trusted Advisor Full, 3rd party software guidance, Architectural
      guidance, Support API

    * Enterprise => Dedicated TAM + best support

8. AWS Cloud Adoption Framework (CAF) -

    * Business Side -

     * Business - Why are we moving to AWS, and what business value will it provide?
     * People - Do our employees have the skills and organization needed for cloud adoption?
     * Governance - How do we control, prioritize, and manage cloud investments and risks?

    * Techinical Side -

     * Platform - How will we build/migrate the actual cloud infrastructure and applications?
     * Security - How do we protect AWS workloads, data, identities, and infrastructure?
     * Operations - How will we run and maintain AWS after deployment?

11. Disaster Recovery Strategies -

    * Backup and Restore -

        * Ideally nothing is running, you just backup the database and condifgurations periodically

        * In case of failures you just rebuild everything from the backups

        * Lowest Cost + Highest Recovery Time
    
    * Pilot Light -

        * We keep a smaller infrastructure running in the DR region i.e pilot - very small version

        * Low - medium cost + Faster Recovery Time compared to Backup and Restore

    * Warm Standby -

        * Entire application is already running in the DR region but with reduced capacity

        * Cost High + Faster Recovery

    * Multi Active Active -

        * Both regions are actively serving users simultaneously, each region having their own DBs with
          read and write access
        
        * Cost Highest + Fastest Recovery
