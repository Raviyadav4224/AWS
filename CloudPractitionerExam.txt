1. AWS Systems Manager (SSM) -

    * It is a hybrid service, that lets you manage EC2 and On-Premise servers at scale

    * Important Features includes -
      Patching automation for enhanced compliance
      Run commands across an entire fleet of instances
    
    * It uses SSM Agent which must be installed on EC2 instance

2. AWS Systems Manager - Session Manager -

    * It creates secure connection to your EC2 and On-Premise instances without the need of SSH Access
      No SSH Keys, No bastion host and No Port 22 needed thus enhancing the security
    
    * It sends the session log data to S3 or Cloudwatch

3. AWS Global Accelerator vs CloudFront -

    Global Accelerator -

        It is for Better Network Path and avoids the Internet and uses AWS global backbone network thus
        reducing the latency of the application

        It uses the nearest AWS Edge locations
        
        2 Anycast IP are created for your application and traffic is sent through Edge Locations

        It is suitable for Gaming applications or IoT as well as Http/Https use cases

    CloudFront -

        It is for content caching
        It also uses the AWS Edge locations to cache the content

    ** CloudFront => WAF (Layer 7) ✅ + Shield (Layer 4) ✅
       Global Accelerator => Shield ✅, WAF ❌ (attach it to the ALB/API Gateway behind it instead)

4. AWS Outposts -

    * It is a small piece of Region installed in your own data center

    * The Outposts rack is physically located in your data center, AWS still manages the Hardware,
      installation, Hardware maintainence etc 

    * It provides Low latency, Data processing is done locally, Used when Data regulatory is required

5. AWS Wavelength -

    Brings AWS services to the edge of the 5G networks
    AWS uses the Telecom provider 5g network for ultra low latency
    Used for Real Time Gaming, Live Video Streaming applications

6. AWS LocalZones -

    Bring AWS resources (compute, database, storage etc) closer to your users i.e comes closer to your city
    Example - AWS Region - N. Virginia (us-east-1), AWS Local Zones - Boston, Chicago, Dallas, Houston, 
    Miami etc

7. AWS Health Dashboard -

    AWS Health Dashboard (Your Account) - How is AWS affecting me 

8. VPC -

    * VPC Peering - 
      
      Connect Two VPC's PRIVATELY using AWS Network as if they were in the same network, the CIDR must
      not overlap with each other, It is not TRANSITIVE i.e for each new VPC we have to configure

    * VPC Endpoints -

        A VPC Endpoint allows resources inside your VPC to privately access supported AWS services without 
        traversing the public internet
        
        It is of two types -
        Gateway Endpoint (S3 and Dynamodb) - EC2 - Route Table - Gateway - S3/Dynamodb
        Interface Endpoint (Rest all AWS Services) - EC2 - Elastic Network Interface(ENI) - Private IP 
        - AWS Service

    * Site To Site VPN -

        Connects an on-premise VPN to AWS over the PUBLIC internet, the connection is encrpyted by default
        On-Premise connects to = Customer gateway (CGW)
        AWS connects to = Virtual private gateway (VGW)

    * Direct Connect -

        Establishes a physical connection between on-premise and AWS
        The connection is PRIVATE, secure and fast

    * AWS PrivateLink -

        AWS PrivateLink enables private connectivity between VPCs and supported AWS services without 
        traffic traversing the public internet
        It ensures secure communication for applications and services

    * AWS Transit Gateway

        AWS Transit Gateway is a highly scalable service that connects multiple VPCs and on-premises 
        networks (using vpn) through a central hub
        It facilitates secure, private connectivity between VPCs and supported services without using 
        the public internet

9. AWS Shared Responsibility Model -

    * AWS Responsibility (Security of the Cloud) -

        Aws is responsible for -
        Physical security of data centers
        Hardware
        Networking infrastructure
        Storage infrastructure
        Virtualization layer (Hypervisor)
        Availability of AWS services

    * Customer's Responsibility (Security in the Cloud) -

        Customer is responsible for -
        IAM users, roles, and permissions
        Data encryption
        Network security (Security Groups, NACLs)
        OS configuration (for EC2)
        Installed applications
        Security patches (for EC2 OS and applications)
        Monitoring and logging
        Compliance of their workloads

    *   | Responsibility                          | AWS   | Customer  |
        |-----------------------------------------|------ |-----------|
        | Physical Security                       |  ✅  |     ❌    |
        | Hardware                                |  ✅  |     ❌    |
        | Networking Infrastructure               |  ✅  |     ❌    |
        | IAM Configuration                       |  ❌  |     ✅    |
        | Security Groups                         |  ❌  |     ✅    |
        | Data                                    |  ❌  |     ✅    |
        | Configuration Management                |  ❌  |     ✅    |
        | Training                                |  ❌  |     ✅    |
        | Patch Management (EC2)                  |  ❌  |     ✅    |
        | Patch Management (Managed Services)     |  ✅  |     ❌    |
        | Service and Communications Protection   |  ❌  |     ✅    |

    ** Service and Communications Protection or Zone Security means configuring Security Groups,
       NACLs, Network Firewall etc

10. AWS WAF, Shield, Network Firewall -

    * Shield (Layer 3 & 4) -

        It is a Free Service available to every AWS account
        It protects against DDoS attacks

    * Shield Advanced (Layer 3 & 4) -

        It is Paid Service
        Protects against COMPLEX DDoS attacks and provides 24/7 Dedicated Response Team
        You need to enable it

    * Web Application Firewall (Layer 7) -

        It protects the web application at Layer 7 i.e Http/Https from SQL Injection, XSS, Rate limitings
        It does NOT works for Route53 and Global Accelerator
        It is not enabled by default

    * Network Firewall -

        It protects your entire Amazon VPC from Layer 3 to Layer 7, It is STATEFULL
        We can inspect any direction - VPC to VPC, In/Out to internet, To/From Direct Connect and 
        Site to Site VPN 

11. AWS Artifact -

      auditors, like AWS ISO certifications, Payment Card Industry (PCI), and System and Organization

    * Artifact Agreements - Allows you to review, accept, and track the status of AWS agreements such as
      the Business Associate Addendum (BAA) or the Health Insurance Portability and Accountability Act
      (HIPAA) for an individual account or in your organization

12. AWS GuardDuty -

    * It is a Threat Detection Service that continuously monitors AWS accounts for suspicious activity
      and uses Machine Learning Algorithms to detects anomalies
    
    * It Detects - Stolen credentials, Cryptocurrency mining, Port scanning, Unusual API activity
    
    * It just detects threats, It DOES NOT block attacks

    * It can be configured with EventBridge rules to notify
    
    * Input Data includes - CloudTrail Logs, VPC Flow Logs, DNS Logs

13. AWS Inspector -

    * It is a Deep security vulnerability scanning service

    * Checks for  CVEs, vulnerable packages, insecure software versions

    * Mainly for - EC2, Lambda dependencies, ECR container images

14. AWS Config -

    * It stores Configuration History of AWS resources i.e what resources exists and who has changed the
      configuration of these resources, Whether they comply with your rules or not

    * Questions that can be solved by AWS Config - 

      Is there unrestricted SSH access to my security groups?
      Do my buckets have any public access?
      How has my ALB configuration changed over time?

    * CloudTrail stores who changed the resource config whereas AWS Config checks what resources got changed

16. AWS Organization -

    * It is a Global Service which allows us to manage multiple AWS accounts

    * Cost Benefits - It provides consolidated billing accross all accounts with a single payment option

    * Combined Usage – combine the usage across all AWS accounts in the AWS Organization to share the 
      volume pricing, Reserved Instances and Savings Plans discounts
    
    * We can restrict account usage using Service Control Policies (SCP)

    * We can create accounts -
        per department, 
        per cost center, 
        per dev / test / prod, 
        based on regulatory restrictions (using SCP), 
        for better resource isolation (ex: VPC), 
        to have separate per-account service LIMITS, 
        isolated account for logging

    * SCP doesn't grants permissions rather acts as a filter, It doesn't allow anything by default
      We need to provide an explicit allow
      Policy Evaluation => SCP => IAM Policies => Resource Policies
